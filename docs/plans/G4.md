## 1. Migration 0062 `distribution` (§7.5 rows 170–175)
- `ops.listing_channel` + `facebook_page` (the Page post's short link; clicks and enquiries per channel as B7.9).
- Enums `platform.social_provider` (facebook_page), `platform.social_channel_state` (verified, failing, revoked),
  `ops.social_post_state` (queued, posted, failed, deleted), `ops.social_post_action` (publish, update, delete).
- `platform.social_channel` (RLS tenant): provider, `page_id`, `page_name`, `token_enc bytea` (tenant DEK, AAD
  tenant / table / `token` / row id — the D-240 / B7.7 pattern), state, `auto_post`, verified / checked stamps,
  `last_error`, revoked stamps; **partial UQ (tenant_id, provider) WHERE state <> 'revoked'**.
- `ops.listing_social_post` (RLS tenant): listing, channel, state, `pending_action`, `external_post_id`,
  `content_hash`, attempts, `next_attempt_at`, `last_error`, posted / updated / deleted stamps; **UQ (listing_id,
  channel_id)**; IX queued by `next_attempt_at`.
- `ops.listing.og_image_document_id` → `core.document`, `og_image_hash`.
- Deviation from the G4-c draft: **no `verified_vacant_at` column** — the badge is computed on read from lease /

  platform invoices identified by their snapshot (`product = line_oa_integration`).

## 2. Public listing (E2)
- **Verified vacant** (`verifiedVacant`, `vacantSince`) on search cards and the detail: no current occupancy, no
  lease in force (`active`, `notice_given`, `ending`), no lease waiting for signature, **and** getproperty holds the
  evidence — the unit had a lease on the platform that ended / was terminated (`vacantSince` = its last day + 1).
  Units without lease history never get the badge (setting `listing.verified_vacant.require_history`, true).
- **Real utility cost** stays D-265 / B7.9 (rates in force + average of the last 3 confirmed bills,
  `listing.utility_history.min_bills`); the pack's "≥ 2 months of smart rollups" is not a second figure (G0 gap note).
- **JSON-LD** (`jsonLd`): schema.org `Offer` with `UnitPriceSpecification` (monthly, THB) and an `itemOffered`
  `Apartment` / `House` / `Accommodation` (floor size m², bedrooms, bathrooms, pets, address, geo, images = the OG
  image URL), `availabilityStarts`, `url` = the public page.
- **OG image** `GET /v1/public/listings/{slug}/og-image` (PNG 1200 × 630: cover photo, rent, title, place, badges,
  logo), rendered with sharp / Pango + Sarabun like the B7.9 cards (no Chromium — D-236's aim), stored as a document
  (kind `other`, unit scope, counted to the quota) and re-rendered only when its content hash changes; `ogImageUrl`
  on the detail. Rate-limited, cacheable 1 h.

## 3. Facebook Page auto-post (E7, D-288)
- Port `FACEBOOK_PAGES` (`page`, `publish`, `update`, `remove`): `FacebookPagesUnavailable` (`off`, default outside
  dev / tests → `facebook.unavailable` 503), `FakeFacebookPages` (`fake-page-token-<name>`; `…revoked…` = OAuth
  error 190; `…busy…` = rate limit 32), `GraphFacebookPages` (Graph API `GET /{page-id}`, `POST /{page-id}/feed`,
  `POST /{post-id}`, `DELETE /{post-id}`; `// UNVERIFIED against live provider`, O-029). Env `FACEBOOK_MODE`
  (`off | fake | real`; default `fake` with fakes, else `off`), `FACEBOOK_GRAPH_VERSION` (`v21.0`).
- `SocialChannelsService`: connect a Page (page id + Page access token; checked with the provider first — a refused
  token is 422 `facebook.page_refused` and nothing is stored), sealed with the tenant DEK, replaces the live one;
  list (never the token), verify (`verified` / `failing`), revoke. Audit, events `social_channel.connected` /
  `.revoked`. Token decrypts audited by the key service; tokens never logged / returned / put in events.
- `ListingSocialService`: subscriber on `listing.published`, `listing.restored` (→ publish), new event
  `listing.price_changed` (emitted by `ListingsService.update` when the rent of a published listing changes → update),
  `listing.closed` / `listing.paused` / `listing.hidden` (→ delete; "delete on let" plus anything no longer public).
  The subscriber only queues (`ops.listing_social_post` per live `auto_post` channel, in the event's transaction);
  the worker job `social-posts` (60 s) calls the provider **after** reading in its own transaction and writes the
  outcome in another: posted / updated / deleted / failed (token refused → channel `failing`, no retry; rate limit
  or 5xx → retry with backoff up to `social.post.max_attempts` (5)). Message = the B7.9 Thai caption with the
  listing's `facebook_page` short link (UTM + lead channel). Audit + events `listing.social_posted` /
  `.social_post_failed` / `.social_post_deleted`.
- Owner: `GET /v1/owner/listings/{id}/social-posts`, `POST …/social-posts/{postId}/actions/retry` (Idempotency-Key).

## 5. Agency LINE OA (E7, D-254 / D-287)
- B7.7 channels already work for every tenant type (agency included): sealed credentials, a webhook URL per channel
  (`/webhooks/line/{webhookKey}`, signature checked with that channel's secret), delivery through the own OA when the
  recipient linked it. G4 adds:
  - **Prospects link the agency's OA**: `GET /v1/prospect/messaging-links/{token}`, `POST …/actions/confirm` (the
    lead / viewing messages of an agency go to prospects, whose login is a prospect token).
  - **Integration fee** as price-plan add-on `line_oa_integration` (seeded for `agency`, kind `addon`, billing unit
    `per_tenant`, no price — O-027): `unitPrice` = monthly fee, `setupFee` = setup. While a priced version is in force
    for the tenant's type, connecting an own OA needs `acceptAddonVersionId` = that version (409
    `messaging.addon_terms_required` with the prices) and the setup fee is invoiced once (`purchase` invoice, line
    kind `setup`); job `messaging-addons` invoices the monthly fee (line kind `messaging_addon`) for each Bangkok
    month a live own OA existed on its first day (the first partial month is free). Unpaid = nothing suspended
    (D-250); LINE bills its message charges to the agency directly. `GET /v1/owner/messaging/addons` shows the offer
    and the invoices.
- Isolation tests: a webhook signed with tenant A's secret on tenant B's URL is 401; a link issued by A's OA links
  only A's channel; messages of B's leads never use A's OA.

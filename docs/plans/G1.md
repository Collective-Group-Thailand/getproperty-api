# G1 — Storage quota, legal hold, storage packages and reclaim (plan)

Step G1 of `docs/prompts/G-growth-api.md` (module E6). Requirements: D-285, D-286 (founder 2026-10-26), D-276 / D-279
(B7 slice stays), O-022 (package prices), O-025 (retention periods ⚖), O-008 (platform issuer / merchant).
Drafts used: `docs/growth-gap.md` §2.1–2.3 and §3 G1, `docs/schema-design.md` §7.5.G rows G1-a … G1-g.

## Reuse (never duplicate B7)
- `StorageMeteringService` (policy from `storage.*` settings, daily snapshot, 80/100 % notices, admission, monthly
  charge), `platform.storage_usage_daily`, `platform.storage_notice`, `GET /v1/owner/storage` (fields kept, body
  extended), `GET /v1/admin/storage/tenants` (extended), `storage.allowance_exceeded` (409 — the only quota code; it
  gains the `storage` problem extension with usage / quota / packages link; no `storage.quota_exceeded`).
- Per-tenant override = a tenant version of `storage.free_gb` (audited by `SettingsService`); new typed endpoint
  `PUT /v1/admin/tenants/{tenantId}/storage-quota` writes that version.
- `platform.retention_policy` (seeded per document class, ⚖) for the legal-hold period — no second table; new seed
  rows for the kinds the seed lacks (tax invoice, debit/credit note, deposit settlement statement, TM30 export).
- Price plans (`kind addon`) are the package definitions; versions stay draft → published, never edited (D-204);
  `unit_price` null = not on sale (O-022).
- Platform invoices (B6.1): issue / payment / receipt / QR subscriber / PDFs.

## Build
1. **Migration 0058** (SQL + Prisma models; §7.5 rows 142–148):
   - `platform.storage_category` enum; `platform.storage_usage` (tenant × category: bytes, objects) — current counters;
   - `platform.document_storage` (one row per counted `core.document`: category, bytes incl. derivatives, objects,
     derivative keys, `counted`) — the ledger behind the counters (deviation from the draft: needed to decrement
     exactly and to know derivative objects for purge / reconciliation);
   - `platform.storage_reconciliation` (append-only nightly report);
   - `platform.document_legal_hold` (document, kind, policy, `retain_until` — null = open-ended until the basis event,
     source, released_at) + trigger: no DELETE, no release before `retain_until`, `retain_until` never shortened;
   - `platform.storage_package` (+ state enum, period enum);
   - platform invoices: `subscription_id` nullable + CHECK (only `purchase` may lack it); `platform_invoice_kind` +
     `purchase`; `platform_line_kind` + `boost`, `success_fee`, `co_broke_fee`, `media_service`, `messaging_addon`,
     `sponsored_broadcast`; `plan_billing_unit` + `per_package`, `per_listing`, `per_recipient`, `per_deal`,
     `percent_of_amount`;
   - backfill of counters / ledger from live `core.document` rows (derivative bytes unknown → first reconciliation).
   - **No `core.*` change**: the database guard is the trigger on the hold table; `core.document` soft delete is
     guarded in the API layer (every delete path checks the hold). A `BEFORE UPDATE OF deleted_at` guard on
     `core.document` would need an asset-core release — recorded as a request, not made in G1.
2. **StorageLedger** (`src/core/storage/storage-ledger.ts`): `count / resize / addDerivative / uncount` in the caller's
   transaction (row lock per tenant × category), `recount` (exact, from the ledger). Called from DocumentsService
   (`complete`, `recordGenerated`, `scan` re-encode + thumbnails / renditions), retention job, listing evidence purge,
   DSR, reclaim purge. Usage of the metering service reads the counters.
3. **Legal hold** (`LegalHoldService`): `recordGenerated` holds legal kinds (receipt, tax invoice, invoice, debit /
   credit note, signed contract + signatures, slip, deposit settlement statement, TM30 export, e-Tax XML) with
   `retain_until` = issue date + policy period (basis "lease end" → open-ended); slips uploaded by residents are held
   at `complete`. Legal documents are written whatever the quota (assert: receipt issued over quota).
4. **Enforcement**: allowance = free (tenant override) + active packages; admission keeps D-276 classes (legal /
   operational always stored; optional held at the allowance unless overage is sold); listing photos are optional;
   problem extension `storage` on 409.
5. **Reclaim**: `GET /v1/owner/storage/files` (largest first, filters, `deletable` + reason), `actions/delete`
   (soft delete, all-or-nothing; held → 409 `storage.legal_hold`; system / evidence files → 409
   `storage.not_deletable`; photo of a live listing → not deletable), `actions/restore` (before purge),
   purge after `storage.reclaim.purge_after_days` (7) → objects + derivatives deleted, counters drop.
6. **Packages**: admin `GET/POST /v1/admin/storage/packages`, `PATCH …/{packageId}` (names, active, visibility);
   prices through the existing price-plan version endpoints. Owner `GET /v1/owner/storage/packages` (catalogue with
   `onSale` + my packages), `POST` purchase (Idempotency-Key) → `storage_package` pending + purchase platform invoice
   (no subscription, line `storage`); `platform_payment.confirmed` (settled) → active (subscriber); expiry job →
   expired (nothing deleted, uploads held when over); auto-renew issues the next period's invoice
   `storage.package.renew_days_before` days ahead; owner cancel of a pending purchase voids nothing (invoice stays for
   Finance) — out of scope, recorded.
7. **Reconciliation**: `StorageInventoryPort` (`list(prefix)`; fake over the in-memory object storage, real
   `ListObjectsV2` — `// UNVERIFIED` not needed, AWS SDK) → per tenant `t/<id>/`: S3 sizes per known key vs ledger,
   orphans and missing objects reported, ledger + counters corrected (`storage.reconciliation.auto_correct`), report
   row; admin `GET /v1/admin/storage/reconciliations`.
8. Listing photos: stored JPEG resized to `storage.images.max_edge_px` before counting (WebP renditions as B7.2).
   Other kinds are not re-encoded (meter photos, slips, inspection photos are evidence checked by sha256).
9. Settings, error codes (th/en), events, audit actions, worker jobs `storage-reconcile` (daily) and
   `storage-maintenance` (hourly), contract, PROGRESS, deployment needs (ListBucket on `t/*`).

## 1. Device protocol 1.3 (additive; meter-only gateways unaffected)
- `Command.type` + **`gate.open`** (cloud → edge on `gp/v1/<gatewayId>/cmd`), `args` = `GateOpenArgs { commandId, gateId, deviceId, reason, visitId?, pulseMs, expiresAt }` (`commandId` = `cmdId`; `deviceId` = the `smart.gate_device` id of the barrier; `pulseMs` 200–10 000; `expiresAt` = `issuedAt + 30 s`, `ttlS` 30). Edge: idempotent by `commandId` (a redelivery never pulses twice), refuses after `expiresAt` (ack `failed`, `error: "expired"`), acks `accepted` → `done | failed` as every command. Cloud: **sent once** (no re-send; a missed command is never replayed later) and expired after 30 s.
- `DeviceEvent.type` + **`gate.state`** with `data` = `GateStateData { gateId, deviceId?, state: open|closed|fault, at, commandId? }` and **`plate.detected`** with `data` = `PlateDetectedData { gateId, deviceId?, plate: { category, number, province? }, confidence (0–1), at, imageRef? }` on `gp/v1/<gatewayId>/events`. `data` is validated per type (invalid → dead letter `invalid_payload`).
- `GatewayConfig.gateDevices?` (only when the gateway drives a barrier / LPR — the config of a meter-only gateway is byte-identical): `[{ deviceId, gateId, kind: barrier|lpr, channel, pulseMs? }]`.
- `contract/device-protocol.json` `x-protocol-version` 1.3, new `$defs` (`GateOpenArgs`, `GateStateData`, `PlateDetectedData`, `PlateReading`, `GateDeviceConfig`, enums `GateBarrierState`, `GateDeviceHardwareKind`), `x-command-args`, `x-event-data`; `docs/contract/device-protocol.md` §3 + changelog line.
- **Device auth**: an event is acted on only when the publishing gateway is the edge device of an **active** `gate_device` of that gate and kind (`plate.detected` → `lpr`, `gate.state` → `barrier`); anything else is stored as a device event, audited `gate.device_event_refused` and ignored. The device event row keeps ids only (no plate).

## 2. Barrier / LPR devices (§7.6 J4-c)
- `smart.gate_device_kind` `lpr_camera` → **`lpr`** (renamed; no row used it). New columns `edge_device_id` → `smart.device` (a provisioned `gateway` of a building of the gate's property, same tenant), `channel` (relay output / camera id on the edge, `^[A-Za-z0-9_.:-]{1,32}$`), `pulse_ms` (barrier, 200–10 000, default setting `gate.barrier.pulse_ms` 800), `hw_state` (open | closed | fault) + `hw_state_at`; CHECK hardware kinds carry edge + channel, tablets none; UQ live (edge, channel).
- Owner `POST /v1/owner/gates/{gateId}/edge-devices` (attach, Idempotency-Key) and `POST …/edge-devices/{gateDeviceId}/actions/detach` (reason); the gate's `barrier` / `lpr` flags follow the live devices; the gateway config is recompiled (published by the existing subscriber). `GET …/devices` lists all kinds.

## 3. Resident vehicles and LPR (§7.6 J4-g2, J4-j new)
- `smart.resident_vehicle` (unit register, no expiry): plate + label; household (co-owner, tenant, co-tenant) adds / removes; every gate role reads. `GET|POST /v1/resident/units/{unitId}/vehicles`, `DELETE …/{vehicleId}`; owner `GET /v1/owner/gate-vehicles?unitId=` (read). The retention job removes a vehicle whose registering login no longer holds a gate role on the unit (moved out / sold) and deletes removed rows after `gate.retention_days`.
- `smart.plate_detection` (one per camera read, `event_id` UQ): plate (province optional), confidence, `image_ref` (opaque edge reference, never fetched), state `pending | matched | claimed | dismissed | expired | ignored`, match (`resident_vehicle | remembered_vehicle | blacklisted | ambiguous | low_confidence | none`), unit, visit. Plate normalisation (Thai digits → Arabic, spaces / dashes dropped, province trimmed); matching on category + number (+ province when read; without a province only a single candidate in the estate matches).
- Known plate (confidence ≥ `gate.lpr.min_confidence` 0.90, not blacklisted): a visit `entered` at once (kind `resident_vehicle` / remembered kind; entry basis `resident_vehicle` / `remembered_vehicle`; `clientRef` = the event id, so a redelivery is idempotent; the household is told only for remembered **visitor** cars) and, when `gate.auto_open_known_plates` (default **false**) and the gate has a live barrier, a `gate.open` (reason `lpr_known_plate`). The same plate at the same gate within `gate.lpr.repeat_seconds` (60) is `ignored`.
- Otherwise a **pending** detection the tablet claims to pre-fill the visit form (`GET /v1/guard/plate-detections`, `POST …/{id}/actions/claim|dismiss`); pending ones expire after `gate.lpr.pending_minutes` (10, swept by `gate-visits`). Event `gate.plate_detected` (ids only) reaches the guard stream.

## 4. Opening the barrier
- Guard `POST /v1/guard/gates/{gateId}/actions/open` {reason `visit | resident | delivery | service | emergency | other`, note (required for other), visitId?} → 202 `{ commands: [{commandId, gateDeviceId, expiresAt}] }` for every live barrier of **the guard's own gate** (another gate = 404); 409 `gate.no_barrier` without one; visit must be of this gate.
- Resident `POST /v1/resident/gates/{gateId}/actions/open` {vehicleId, location?: {lat, lng, accuracyM?}} — only a live resident vehicle of a unit I hold a gate role on today in the gate's estate (else 404); `gate.resident_open.enabled` (default true; false → 403 `gate.resident_open_disabled`); `gate.resident_open.require_geofence` (default false) → location required (422), estate without coordinates → 409 `gate.geofence_unavailable`, farther than `gate.resident_open.radius_m` (300) + accuracy (capped 100 m) → 403 `gate.outside_geofence`; only the decision (`inside` true/false) is audited — the coordinates are never stored or logged. `GET /v1/resident/gates` lists the gates I may open with my vehicles.
- **Rate limits** (DB, under a row lock on the gate — exact with several API processes): one open per gate per `gate.open.min_interval_seconds` (3) → 429 `gate.open_rate_limited` + `Retry-After`; a resident at most `gate.resident_open.max_per_hour` (12) → 429.
- Every open: `smart.device_command` per barrier + audit `gate.open_requested` (gate, by, reason, visit) + event `gate.open_requested` (gate stream); the ack (`device.command_finished`) also reaches the gate stream. Visit timeline `gate_opened`.

## 5. SOS / incidents (§7.6 J4-i, J4-k new)
- `smart.incident` completed: state `open → acknowledged → resolved` (+ `cancelled`; enum value `closed` renamed `resolved`), `gate_id`, `raised_by_user_id`, `resolved_at/_by`, `resolution_note`, `cancelled_at`, `cancel_reason`; `visit_ids` = visits of the estate **entered at or before the SOS and not exited before it minus `gate.incident.visit_window_minutes` (30)**. `smart.incident_event` (append-only, id = domain event id): raised, acknowledged, resolved, cancelled, note.
- Resident `POST /v1/resident/sos` (Idempotency-Key; unitId, kind fire|medical|intrusion|other, note ≤ 500, photo inline ≤ 2 MB) — gate roles of the unit; **an open SOS of the same unit by me is returned instead of a second one** (`existing: true`); more than `gate.sos.max_per_hour` (5) per login → 429 (never silently dropped). `GET /v1/resident/sos[/{id}]` (status: acknowledged by the guard / office, when), `POST …/{id}/actions/cancel` within `gate.sos.cancel_seconds` (30) → `cancelled` (409 after).
- Fan-out at once (event `gate.incident.raised`, **urgent**): every gate of the estate (`gate:<id>` stream — the tablet shows the takeover banner; `GET /v1/guard/incidents?state=open` on reconnect), owner / manager / committee (manager routes) / staff by in-app + LINE; resident realtime `unit:<id>`. `gate.incident.acknowledged` → the raising resident (LINE + in-app). Guard `GET /v1/guard/incidents`, `GET …/{id}`, `POST …/{id}/actions/acknowledge|resolve`, `POST /v1/guard/incidents` (the tablet's own SOS button, source `guard`). Owner `GET /v1/owner/incidents` and `…/{id}` with `reason` (5–500, audited `gate.incident_log_read`, like the visit log) incl. the timeline and the linked visits; `POST /v1/owner/incidents/{id}/actions/acknowledge|resolve`.
- Permissions: `gate.incident.read` (owner, manager, committee, staff), `gate.incident.manage` (owner, manager, staff); guard role + `gate.open`, `gate.incident.respond`.

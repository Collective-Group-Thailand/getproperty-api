## 1. Vendors (§7.6 J2-l)
- `juristic.vendor` wraps a `core.party` (company or person; UQ tenant × party): name, categories (enum array `juristic.vendor_category`: security, cleaning, gardening, lift, pump, fire_system, electrical, plumbing, pest_control, pool, cctv, waste, building_works, professional, insurance, other), contact person / phone / e-mail, bank **masked only** (bank name, account name, last 4 digits — the full number is never stored: payments are recorded, never executed), state `active · blocked` (+ reason), note.
- **Tax id** (13 digits, checksum) lives on the party (`core.party.tax_id`) — the column J2.1's 50 ทวิ already reads — so an expense request paid to a vendor withholds with the vendor's tax id. DTOs show `taxIdHint` (last 4) only. Creating a vendor without `partyId` creates the party.
- A blocked vendor cannot get new contracts, quotations or expense requests (422 `vendor.blocked`).

## 2. Contracts (§7.6 J2-m)
- `juristic.vendor_contract`: building, vendor, title, scope, category, **SLA terms** (jsonb `[{priority low·normal·high·urgent, responseHours, resolveHours}]`), `starts_on` / `ends_on`, `renewal_notice_days` (0–365), value, expense account + optional WHT key (instalment requests), **instalment plan** (`frequency monthly · quarterly · semiannual · annual · once`, `dueDay` 1–28, `amount`, `vatAmount`, `firstDueOn`) → rows `juristic.vendor_contract_instalment` generated at activation within the term, penalty clauses (text), documents (`vendor_contract_document`, kinds contract · amendment · insurance · guarantee · other), quotation round / resolution, `renews_contract_id`.
- States `draft → active → expired | terminated`. **Activate** (Idempotency-Key): vendor active, expense account set when an instalment plan exists, the **quotation rule** (§3) — value above `juristic.quotation_threshold` needs the contract's quotation round awarded to this vendor (or, for a renewal, an adopted resolution of the building; 422 `vendor_contract.quotations_required`); instalments generated (Σ shown; no instalment before `starts_on` or after `ends_on`). **Renew** (Idempotency-Key): a successor draft copying the terms with the new period (starts the day after the current end unless given), value / plan optional. **Terminate** (Idempotency-Key, reason, effective date ≥ today): state `terminated`, instalments due on/after the date cancelled, linked PM plans deactivated.
- Job **`vendor-contracts`** (hourly, idempotent): (a) each `scheduled` instalment with `due_on − juristic.contract_instalment_lead_days ≤ today` (Bangkok) of an active contract becomes **one submitted expense request** (J2.1 model: band snapshot, number `EXP`, approval notification; payee = the vendor's party, line on the contract's expense account with its WHT key; `vendor_id`, `vendor_contract_id`; requester = the user who activated the contract — maker-checker keeps them out of the approval) — the instalment row is locked and moves to `requested` with the request id (UQ), so a re-run creates nothing; (b) **expiry alerts** at each of `juristic.contract_expiry_alert_days` (90 / 60 / 30) before `ends_on`: one `vendor_contract_alert` row per (contract, days, end date) (UQ) + event `juristic.vendor_contract.expiring` → owner + manager + committee (manager routes), in-app + LINE; a late first run sends only the nearest threshold; (c) active contracts past `ends_on` → `expired` (scheduled instalments cancelled).

## 3. Quotation rounds (§7.6 J2-n, J2-o)
- `juristic.quotation_round` (building, title, description, category, estimated amount) `open → awaiting_approval → awarded | cancelled`; `juristic.quotation` (vendor, amount, VAT part, valid until, document **required**, note; UQ round × vendor; only while open; blocked vendor 422).
- **Award** (Idempotency-Key) picks a quotation (valid on the award day), the outcome (`contract` → a contract draft for the vendor and amount; `expense` → an expense request draft with the quotation attached, needs an expense account) and the basis: `resolution` (adopted, same building → awarded at once) or `approval` (band of `juristic.approval_bands` for the amount snapshotted; distinct band-role users other than the requester approve — maker-checker trigger like expenses; one rejection reopens the round). **Rule**: when the amount is above `juristic.quotation_threshold` and the round has fewer than 3 quotations, `fewerQuotationsReason` (10–1000) is required (422 `quotation.minimum_not_met`) and the award always needs the resolution or the band approvals. The outcome is created when the round is awarded.
- Expense requests linked to a vendor (not to a contract) above the threshold need an awarded `quotationRoundId` of that vendor to be submitted (422 `expense.quotations_required`). Unlinked J2.1 requests are unchanged (assumption: the rule binds vendor purchases; the vendor link is what the threshold is checked on).

## 4. Evaluations (§7.6 J2-p)
- `GET …/vendor-contracts/{id}/sla-breaches?month=YYYY-MM`: the month's work orders of the contract's building assigned to the vendor's party or generated by a PM plan of the contract (not cancelled): **response** (accepted / checked in − assigned, else now) above the priority's `responseHours`, **resolve** (completed − the request's or work order's creation, else now) above `resolveHours`, and **request SLA** (the linked service request's workflow SLA breached).
- `POST …/evaluations` (Idempotency-Key, `juristic.vendor.evaluate`: owner, manager, committee) per contract × month (UQ; month within the contract term and not in the future): scores 1–5 per criterion of `juristic.vendor_evaluation_criteria` (all required), incidents + note; the SLA breaches are **pulled** (count + items snapshotted); score = average (2 decimals). Immutable (409 `vendor_evaluation.exists`).
- Contract detail: evaluations and a **trend** (last 6: average, last, `improving · declining · steady`, SLA breaches) shown for renewal decisions.

## 5. Preventive maintenance (§7.6 J2-k)
- `ops.maintenance_plan.vendor_contract_id` (FK, null): plan create / update accept `vendorContractId` (contract of the same tenant and building, not ended). The sweep skips a plan whose contract is not active; a plan without its own assignee is assigned to the **vendor's party**. Contract detail lists its plans (next due, last work order). Terminate deactivates them.

## 6. Expense requests
- `juristic.expense_request` + `vendor_id`, `vendor_contract_id`, `quotation_round_id` (FKs; CHECK contract ⇒ vendor). Create / update accept `vendorId` (payee party + name from the vendor), `vendorContractId` (same vendor, building), `quotationRoundId` (awarded to the vendor). DTO gains the three ids and `vendorName`.

## 7. RBAC, menu, settings, notifications
Permissions `juristic.vendor.read` (owner, manager, accountant, staff, committee, auditor), `juristic.vendor.manage` (owner, manager, accountant), `juristic.vendor.evaluate` (owner, manager, committee); award approvals use `juristic.expense.approve` + the band roles. Menu `juristic_vendors`, `juristic_vendor_contracts`, `juristic_quotations`. Settings `juristic.quotation_threshold` ("50000.00"), `juristic.contract_expiry_alert_days` ([90, 60, 30]), `juristic.contract_instalment_lead_days` (7), `juristic.vendor_evaluation_criteria` (quality, timeliness, communication, safety). Template `juristic.vendor_contract.expiring` th / en.

# G6 — Audience, marketing consent and sponsored broadcast (plan)

Step G6 of `docs/prompts/G-growth-api.md` (module E4). Requirements: **D-287** (sponsored broadcast through
getproperty's own LINE OA to people who chose to receive recommendations; separate marketing consent; frequency cap),
D-291 (every price / cap / window is a setting or price-plan version), D-025 (PDPA consent, minimisation, DSR), O-023
(LINE Thailand has not confirmed sponsored listings through the getproperty OA → `broadcast.sponsored.enabled=false`;
O-023 already exists from G0 and is reused), O-027 (price per recipient and campaign minimum not set → the product is
seeded without a price), O-020 (no payment gateway — a purchase platform invoice). LINE stays on the **fake** adapter.

## 1. Consent purpose and preferences (G6-a, G6-b)
- New purpose **`platform.recommendations`** (audience `prospect`, optional, controller Collective → consent rows with
  `tenant_id` NULL). Plain-language th / en text (⚖ draft) incl. a **profiling note** (what we use: only what the
  person typed; what we never use: special-category data, the landlord's data, payment history). Kept **alongside**
  G8's `resident.relocation` (narrow: a leaving resident's destination) — not merged, not conflicting.
- Never pre-ticked: the API never assumes a grant; a grant is an explicit `consentVersion` equal to the current version
  in the request. A newer purpose version makes the old grant count as not granted (re-consent).
- `platform.audience_preference` (one row per login, RLS **platform_only** — deviation from the draft's "P-own": the
  app role has no actor-row policy; every access is through the service with the actor's id): area slugs (≤ 10, from
  `GET /v1/public/listings/areas`), budget min / max, unit kinds (`ops.portfolio_unit_kind`), move-in window,
  language (th / en / my / km / lo / zh), own quiet hours (start / end, optional), `consent_id`, `withdrawn_at`.
  **No special-category fields exist** (no nationality, religion, health, gender, age); the segment schema is a closed
  whitelist (unknown keys → 400).
- Withdraw in one tap: consent row `granted=false` + `withdrawn_at`; pending deliveries cancelled at once; preferences
  unusable immediately and deleted after `audience.preferences.keep_days_after_withdrawal` (30; 0 = at once). DSR
  export includes preferences + history; DSR erasure deletes both.
- Endpoints (resident and prospect, one LINE login): `GET/PUT /v1/{resident|prospect}/me/recommendations`,
  `POST …/me/recommendations/actions/withdraw`, `GET …/me/recommendations/history` (what was sent to me: campaign
  date, listings, sponsor, labelled ad).

## 2. Sponsored campaigns (G6-c, G6-d)
- Product = price plan `sponsored_broadcast` (add-on, billing unit `per_recipient`, terms `{product:
  sponsored_broadcast, minimumRecipients: 500}`), seeded **without a price** (O-027).
- `platform.sponsored_campaign` (RLS tenant = buyer): name, `listing_ids` (1–`broadcast.sponsored.max_listings`, the
  buyer's own **published** listings), `segment` jsonb (areas, budget, unit kinds, move-in window, languages — closed
  schema), `max_recipients`, snapshot of the price-plan version / price per recipient / VAT rate / minimum at schedule,
  `scheduled_at`, state `draft | scheduled | sending | sent | cancelled | rejected`, `estimated`, `delivered`,
  `clicks`, platform invoice, stamps.
- `platform.sponsored_delivery` (RLS **platform_only**, never visible to the buyer): campaign × user (UQ), state
  `pending | sent | failed | cancelled`, `batch_id` (= LINE `X-Line-Retry-Key`), language, sent_at; IX (user, created)
  for the cap; deleted after `broadcast.sponsored.delivery_keep_months` (12) — campaign counters keep the aggregates.
  Deviation from G6-d: **no per-person click column** — one multicast message is identical for everyone, so clicks are
  counted per campaign link only (more conservative).
- `platform.sponsored_campaign_link` (RLS tenant): one short code per campaign × listing (`<web>/s/<code>`, the same
  short-link page as the D-268 share kit); opening it counts the campaign click and answers channel `line_sponsored`
  (new `ops.listing_channel` value), so the enquiry carries the channel.
- Owner endpoints: `GET /v1/owner/sponsored-campaigns/product` (gate, price, minimum), `POST
  /v1/owner/sponsored-campaigns/estimate` (stateless, aggregate only: below the minimum the count is not shown),
  `GET/POST /v1/owner/sponsored-campaigns`, `GET …/{id}`, `POST …/{id}/actions/schedule` (Idempotency-Key; gate on,
  priced, listings public, estimate ≥ minimum, snapshot), `POST …/{id}/actions/cancel` (draft / scheduled), `GET
  …/{id}/report` (sent, opened = null, clicks, leads attributed — aggregates only, no person). Cross-tenant → 404.
- Admin: `GET /v1/admin/sponsored-campaigns`, `POST …/{id}/actions/reject` (reason), `GET/PUT
  /v1/admin/broadcast/settings` (enabled, cap, quiet hours, attribution days — settings versions), `POST
  /v1/admin/broadcast/consent-texts` (a new `platform.recommendations` version; everyone re-consents).
- Send job `sponsored-broadcasts` (every minute): does nothing while the gate is off; scheduled → sending at
  `scheduled_at`; each pass selects people **at send time**: consent granted at the current version, active login with
  a LINE id, preferences matching the segment and at least one listing's rent / kind, not yet sent this campaign,
  under the weekly cap (`broadcast.sponsored.max_per_week`, rolling 7 days), outside their quiet hours (own, else
  `broadcast.sponsored.quiet_hours`); writes pending deliveries, re-checks consent right before the provider call
  (withdrawn meanwhile → cancelled), multicasts per language in batches ≤ 500 through the new
  `LINE_MULTICAST` port (fake in dev / tests; real adapter UNVERIFIED), marks sent. Completes when the quota is reached,
  nobody else matches, or `broadcast.sponsored.send_window_hours` (24) after the start passed → `sent`, and a
  `purchase` platform invoice line `sponsored_broadcast` = delivered × price per recipient (+ VAT) — billing per
  delivered recipient. Rejected campaigns are not billed.
- Message: Flex carousel, each bubble labelled "โฆษณา · Sponsored" with the OG card image, title, rent, area and the
  campaign short link; a last bubble "ทำไมฉันได้รับข้อความนี้ / เลิกรับ" linking to the LIFF recommendations page
  (one-tap withdraw there).
- Events (outbox) + audit: `audience.preferences_updated`, `audience.withdrawn`, `sponsored_campaign.created|
  scheduled|sending|sent|cancelled|rejected`.

## 3. Settings (D-291)
`broadcast.sponsored.enabled` (false, O-023), `broadcast.sponsored.max_per_week` (2), `broadcast.sponsored.quiet_hours`
(21:00–08:00 Asia/Bangkok), `broadcast.sponsored.max_listings` (5), `broadcast.sponsored.send_window_hours` (24),
`broadcast.sponsored.attribution_days` (7), `broadcast.sponsored.delivery_keep_months` (12),
`audience.preferences.keep_days_after_withdrawal` (30).

# G7 — Self-viewing with time-boxed door codes (plan)

Step G7 of `docs/prompts/G-growth-api.md` (module E8). Requirements: D-289 (1) (self-viewing with temporary door
codes for verified prospects, vacant units with a lock only, never touching resident credentials, D-071 unchanged),
D-252 / D-281 (viewings, prospect audience), D-267 (e-KYC identity verification), D-070 / D-211 (access credentials,
lock vendor port), D-072 (work orders), D-291 (every value a setting). Open: **O-024** (insurance partner and visitor
terms — self-viewing stays behind `viewing.self.enabled`, default false) and the new **O-031** (agency listings on the
owner's lock; visitor-terms wording; log retention). Drafts: `docs/schema-design.md` §7.5.G rows G7-a, G7-b.
Never duplicate B7.3: `ops.listing_viewing`, `ops.listing_availability`, the slot rules and the owner's
confirm / decline / complete flow stay; G7 adds a mode, identity, the access window and the door code.

## 1. Migration 0061 `self_viewing` (§7.5 rows 165–169)
- Enums `ops.viewing_mode` (accompanied, self), `ops.viewing_access_state` (issued, entered, exited, expired,
  no_show, cancelled).
- `ops.listing_viewing`: `mode` (default accompanied), `identity_verification_id` → `platform.identity_verification`,
  `visitor_terms_version` smallint; CK self ⇒ identity + terms.
- `ops.viewing_access` (new, RLS tenant): one per self viewing — listing, unit, building, prospect login, unit lock,
  state, `valid_from` / `valid_to` (CK to > from), entered (+ source `prospect | lock_log`) / exited / closed stamps,
  close reason, first code reveal + count, incident note / time, `work_order_id`, `overstay_alerted_at`, version;
  **EXCLUDE (prospect_user_id =, tstzrange(valid_from, valid_to) &&) WHERE closed_at IS NULL** (one open code window
  per person at a time).
- `smart.access_credential.viewing_id` → `ops.listing_viewing` (CK only `visitor` holders, with an end) — deviation
  from the draft's single `access_credential_id`: a viewing gets one PIN on the unit lock **and** the building doors.
- Trigger `smart.viewing_credential_vacancy_guard`: a viewing credential is refused by the database when the unit has
  a current occupancy or a lease in force (`access.unit_occupied`).

## 2. Rules and services
- `self-viewing-rules.ts` (pure, unit-tested): code window (`slot start − viewing.self.code_early_minutes` …
  `slot start + viewing.self.code_minutes`), whether the code may be shown now, the requirement list
  (identity, phone, terms), overstay.
- Availability windows get an optional `mode` (`accompanied` default, `self`); exceptions stay accompanied-only.
  Public slots carry `mode`; self slots are offered only when the listing is eligible (setting on, own unit lock,
  vacant, listing tenant runs the lock).
- `SelfViewingService` (ops-listings): eligibility; booking checks (setting, verified identity via e-KYC + verified
  phone, current visitor-terms version, vacant, lock, no overlapping self viewing); on the owner's confirm: re-check,
  `ops.viewing_access` + visitor credentials (same random PIN on the unit lock and building doors, via
  `AccessCredentialsService.issueIn`, vendor sync after commit through the fake adapter); reveal inside the window only
  (audited decrypt, never stored in clear, never in events, audit metadata or logs); arrive / leave / incident;
  owner's early end; closing on cancel / decline / reschedule / lost / lease activation / completion (credentials
  revoked in the same transaction); sweep (expired → `no_show` or `expired`, overstay alert, log purge after
  `viewing.self.log_retention_days`); lock-log hook (a successful unlock with a viewing credential = entered).
- Incident → `ops.work_order` (kind `inspection`, priority high) on the unit through `WorkOrdersService.createIn`,
  owner alerted.
- Prospect phone verification (`POST /v1/prospect/me/phone/otp`, `POST /v1/prospect/me/phone`; OTP purpose
  `phone_verify`; `auth.identity_in_use` when another login holds the number).

## 3. Endpoints (contract)
- Prospect: `GET /v1/prospect/me/self-viewing` (requirements + visitor terms), phone OTP / verify,
  `POST /v1/prospect/listings/{slug}/viewings` (+ `mode`, `visitorTermsVersion`),
  `GET /v1/prospect/viewings/{id}/access-code` (`Cache-Control: no-store`),
  `POST /v1/prospect/viewings/{id}/actions/arrive|leave|report-incident` (Idempotency-Key).
- Owner: `PUT /v1/owner/listings/{id}/availability` (+ `weekly[].mode`), viewings carry `mode` + `access`,
  `GET /v1/owner/listing-viewings/{id}/access-log` (audited), `POST …/actions/end-access` (Idempotency-Key).
- Public: viewing slots carry `mode` and `selfViewing`.

## 4. Settings, events, notifications
- Settings: `viewing.self.enabled` (false; platform + tenant; O-024), `viewing.self.code_minutes` (30),
  `viewing.self.code_early_minutes` (5), `viewing.self.overstay_minutes` (30), `viewing.self.log_retention_days`
  (365), `viewing.self.visitor_terms` (version 1 draft th / en, ⚖ O-024).
- Events (outbox): `listing.self_viewing_access_issued`, `…_entered`, `…_exited`, `…_closed`, `…_incident`,
  `…_overstayed`, `access.viewing_door_opened`. Owner / manager / staff alerted on entry, incident, overstay
  (in-app + LINE).

## Deliverable 1.3 — Identity, tenancy & RLS, asset core services, settings, tariffs, outbox, notifications, documents, audit, privacy, workflow engine
**Auth (contract §4)**: operators `POST /v1/auth/operator/otp/request|verify` (SMS OTP, 6 digits, rate & attempt limits), `POST /v1/auth/operator/login` (email + password + optional TOTP); residents `POST /v1/auth/resident/line` (LIFF id-token verification, account linking to parties), `POST /v1/auth/resident/otp/request|verify` (magic-link fallback); technicians `POST /v1/auth/technician/line` (same LINE exchange, `work_order:` scopes; usable from B5); platform `POST /v1/auth/platform/login` (TOTP mandatory); devices `POST /v1/device/bootstrap` (provisioning code → CSR signed by the platform CA → certificate + device JWT; EMQX ACL row written); `refresh` (rotation + reuse detection), `logout`, JWKS. Passwords argon2id. `GET /v1/owner/me` (tenants, current tenant + type, roles, permissions, **menu entitlements**, feature flags, subscription state), `/v1/resident/me` (leases, units, language, consent state), `/v1/staff/me`, `/v1/technician/me`, `/v1/admin/me`.
**Tenancy, RBAC & RLS**: permission catalogue (`resource.action`) in code → seeded; `@Can()` guard; `TenantScoped` repository base adding `tenant_id` to every query **and** `withTx` running `SET LOCAL app.tenant_id` (and `app.actor_*`) on a non-owner connection role so RLS applies; tests including ids in URLs, file keys, exports, cursor tokens, and direct SQL under the wrong `app.tenant_id`; `building:` scope for Staff limited to buildings; **support grants**; admin endpoints for platform users; operator endpoints for memberships, role assignment, invitations; `docs/rbac.md` generated from code.
**Asset core services** (over `collective-asset-core` tables): tenant create/update (`type`, plan, company data — legal name, tax id, address, VAT-registered flag, logo), tenant bank account (add/change → OTP to Owner's phone → effective; history kept), property/building/floor/unit CRUD primitives used by B2, party primitives with per-tenant PII encryption (`core.tenant_data_key`, decrypt audited), `asset_access_grant` service (create/revoke/check, audited), building operator change (closes the `building_operator_period`, re-points grants — no data copy).
**Settings & utility tariffs**: platform settings (platform admin), tenant settings (Owner; some Manager), property overrides; `settings.at(key, date, {tenantId, propertyId})`; cache with invalidation on change event; utility tariffs: admin CRUD of versions with `effective_from`, publish with verification flag, `GET /v1/owner/utility-tariffs/current?utility=&provider=` returning the structure and the **effective average rate** function inputs used by the compliance engine (D-021a, D-140).
**Compliance acknowledgements**: `platform.compliance_acknowledgement` service (who, when, IP, user agent, rule, values shown, legal text version) and the `409 compliance.acknowledgement_required` problem shape (contract §3); used by rate plans (B4.2).
**Workflow engine (D-159)**: generic state machine + SLA timers on `ops.workflow_definition/instance/event/timer` — definitions in code (versioned, seeded), `start(subject, definitionKey)`, `transition(instance, event, actor)` with guards, SLA due dates from settings and the business calendar, timers fired by the worker (exactly once), breach events, history as `workflow_event`; built to move to `collective-shared` later (no getproperty imports inside the engine). First consumers: deposit settlement 7-day clock (B2.4), dunning (B4.5), service requests (B5.1).
**Outbox & events**: `DomainEvents.record(tx, event)` → `platform.domain_event` + `platform.outbox_message` in the caller's transaction; worker relay → BullMQ topics with backoff, dead-letter, admin list/replay. Envelope: `id, type, aggregateType, aggregateId, tenantId, buildingId, actor, occurredAt, correlationId, causationId, payload`. Integration events (`bridge.integration_event`) reuse the relay with the D-153 contracts; consumers arrive with D1/D2.
**Notifications**: templates (Handlebars; LINE Flex JSON, SMS, MJML email, in-app; th/en, versioned, preview, test send), channels (LINE Messaging push to linked residents/operators, SMS, email, web push, in-app), routing matrix per event × audience × channel (owner-configurable for resident-facing events), preferences & PDPA consent gating, quiet hours for non-urgent resident messages (default 21:00–08:00), idempotent per `(event_id, recipient, channel)`, delivery log with provider message ids.
**Realtime & web push**: realtime auth per surface (payload = ids + type only); VAPID subscriptions.
**Documents (files)**: presign (single + multipart), `core.document` rows (storage key, sha256, mime, size, dimensions, scan status, retention class: `meter_photo`, `inspection_photo`, `slip`, `id_document`, `contract`, `logo`, …, scope building/unit/party), `platform.attachment` links, async virus-scan interface + fake, thumbnails, signed downloads, retention job per policy.
**Audit**: security, money and PDPA-relevant actions (login, role change, permission denied, setting/tariff change, bank account change, export, support-grant use, consent change, DSR, PII decrypt, grant change, operator change).
**Privacy**: consent purposes (versioned), consent capture endpoint for residents and operators, DSR (access/erasure) workflow with the tenant as controller and Collective as processor (blueprint compliance), retention policies job.
**Acceptance**: e2e — operator OTP login → `/v1/owner/me` with menu; platform login with TOTP; resident LINE token exchange (fake) → `/v1/resident/me`; device bootstrap → certificate → EMQX ACL row; a token of one audience rejected on other prefixes; cross-tenant id → 404 in every B1 endpoint and invisible under RLS; a grant makes one building visible to another tenant for one module only; tenant setting with future `effective_from` resolves by date; utility tariff for a given date returned; bank-account change blocked until OTP; support grant required for Support reads and audited; a mutation writes audit + event + outbox atomically and a subscriber receives it exactly once; a workflow instance breaches its SLA on a fake clock and emits the breach event once; notification respects consent and quiet hours.
